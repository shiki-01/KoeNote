# KoeNote 要件定義書

Oct 19, 2026 · @shiki

## 1. 実現可能性の結論

実現可能です。ただし「DAW側に直接反映する」には、通常のVST3インサートではなく **ARA2（Audio Random Access）対応プラグイン** として実装する必要があります。本プラグイン「KoeNote」は、Melodyne型のノート単位ボーカル編集ツールです。

| 論点 | 判断 | 根拠 |
| --- | --- | --- |
| ピッチ・タイミング編集 | 可能 | 単旋律のボーカルに限定すれば、解析・加工とも既存の手法で実用品質に達します。 |
| DAWへ直接反映 | ARA2が必須 | 通常のVST3は再生中の音声ストリームしか受け取れず、クリップ全体の参照やタイムライン上の波形の置き換えができません。 |
| 元音源からのMIDI抽出 | 可能 | ピッチ推定結果をノート分割してSMFとして書き出します。DAWへはファイルのドラッグ&ドロップで渡します。 |
| MIDIをターゲットに適用 | 可能 | 取り込んだノートをターゲットピッチとして編集内容に反映します。 |
| 無料配布 | 可能 | VST3 SDK（3.8以降MIT）、ARA SDK（Apache 2.0）、JUCE 8（AGPLv3）を使えば、OSSとして無料公開できます。ニューラルボコーダーの公開重みには非商用条件が付くものがあり、同梱方法に注意が必要です（9章）。 |
| 品質面 | 要検証 | Melodyne同等の品質は開発期間と声質の多様性への対応が課題です。まず単旋律ボーカルの標準的な品質を目標にします。 |

ARA2非対応のDAWでは、再生中にオーディオをキャプチャして編集し、次回再生から反映する「キャプチャモード」に機能が限定されます（6章）。タイミング編集は、ARA2環境の方が大幅に自由度が高くなります。

基準DAWの「Cakewalk」は、旧無料版のCakewalk by BandLabが2025年に提供終了し、後継の **Cakewalk Sonar** に移行しています。Cakewalk Sonarには無料版があり、ARAに対応しているため、本書ではCakewalk Sonarを基準DAWとします（[Cakewalk Sonarの無料提供](https://soundgale.com/cakewalk-sonar-is-back-again/)、[旧版の終了経緯](https://en.wikipedia.org/wiki/Cakewalk_by_BandLab)）。

個人開発での工数は、MVP（ARA2、ノート編集、基本的な加工）まで約6〜8か月、MIDI連携・タイミング整列・ニューラル加工を含むv1.0まで約11〜16か月と見積もります（7章）。

## 2. 目的・スコープ

歌声の音程とタイミングを、DAWを離れずに高精度で補正できる無料のボーカル編集プラグインを作ります。

- **想定ユーザー**: 歌ってみたや自作曲のボーカルをミックスするDTM利用者（歌い手が中心、ボカロ系ボーカルも対象）
- **対象素材**: 単旋律のボーカル（ハモリ・ダブルは別トラックとして個別に処理）
- **対象外（初期）**: 和音楽器の編集、リアルタイム入力のピッチ補正（オートチューン用途）、歌声合成エンジンとしての利用
- **目標**: ノート単位の編集結果が、DAWの再生・ミックスダウンにそのまま反映される

## 3. 機能要件

優先度は M（必須・MVP）、S（重要・v1.0）、C（任意・v1.x以降）で表します。

| ID | 機能 | 内容 | 優先度 |
| --- | --- | --- | --- |
| F-01 | ARA2連携 | クリップ全体の音声を取得し、編集結果をDAWの再生系へ返します。 | M |
| F-02 | ピッチ解析 | F0（基本周波数）と有声・無声区間を推定し、ノートに分割します。 | M |
| F-03 | ピアノロール表示 | 波形とピッチ曲線をノートのブロックとして表示し、ズーム・スクロールに対応します。 | M |
| F-04 | ノートのピッチ編集 | ノートの上下移動、ピッチ中心の補正量、スナップ（スケール・半音）を設定します。 | M |
| F-05 | ピッチ曲線の微調整 | ビブラート量、ピッチドリフト、ピッチ遷移の滑らかさをノート単位で調整します。 | M |
| F-06 | タイミング編集 | ノートの開始位置・長さを変更し、タイムストレッチで反映します。子音部は伸縮を抑えます。 | M |
| F-07 | ノートの分割・結合・境界編集 | 自動分割の誤りを修正するため、ノートの分割、結合、境界の移動を行います。 | M |
| F-08 | Undo/Redo・状態保存 | 編集履歴を保持し、プロジェクトファイルへ編集内容を保存・復元します。 | M |
| F-09 | フォルマント制御 | ノート単位のフォルマントシフトと、ピッチ変更時の声質保持を行います。 | S |
| F-10 | 音量・ゲイン編集 | ノート単位のゲイン調整と、ブレス・子音の個別調整を行います。 | S |
| F-11 | MIDI抽出 | 元音源のノートをSMFとして書き出し、DAWへドラッグ&ドロップで渡します。 | S |
| F-12 | MIDIをターゲットに適用 | SMFのノートをターゲットピッチ・タイミングとして取り込み、各ノートを合わせます。 | S |
| F-13 | タイミング整列 | ガイド音声（リードボーカル）にDTWで時間軸を合わせます。ダブルやハモリの整列に使います。 | S |
| F-14 | テンポ・グリッド同期 | DAWのテンポマップに沿ったグリッド表示とノートのクオンタイズを行います。 | S |
| F-15 | キー・スケール検出 | 解析したノートからキーとスケールを推定し、F-04のスナップ候補に設定します。 | S |
| F-16 | 一括補正 | ピッチ補正強度、ビブラート保持、タイミングのクオンタイズ強度を一括で適用します。 | S |
| F-17 | ニューラル加工 | 声質劣化の少ないニューラルボコーダーによる加工を選択できるようにします。 | S |
| F-18 | A/B比較・バイパス | 編集前後の音声を、選択範囲単位で即座に切り替えて試聴します。 | S |
| F-19 | 非ARA環境用キャプチャモード | 再生中にキャプチャした音声を編集し、次回再生から反映します。 | C |
| F-20 | 歌詞・音素表示 | 音素アライメントを利用し、子音区間の保護と編集対象の判別を支援します。 | C |
| F-21 | ARA経由のノート提供 | ARAのノート情報をホストへ提供し、対応DAWでのオーディオ→MIDI変換に使えるようにします。 | C |

### MIDI連携の動作

- **抽出（F-11）**: F-02の結果から、ノートの開始・終了・音高・ベロシティ（音量由来）を生成してSMFを出力します。ピッチ曲線はピッチベンドとして出力するかを選択できます。
- **適用（F-12）**: 取り込んだノートと解析済みノートを時間的に対応付け、ピッチ・タイミングの目標値として設定します。適用強度（0〜100%）を指定でき、対応付けできないノートは手動で割り当てます。
- **DAWとの受け渡し**: DAWのMIDIトラックを直接読み取る方法はホストの対応が限られるため、SMFの読み込みを基本とします。ARAのノート情報提供（F-21）は、対応DAWでの補助手段とします。

## 4. 非機能要件

| 区分 | 要件 |
| --- | --- |
| 対応OS | Windows 10/11（x64）。macOS（Apple Silicon）はv1.x以降に対応します。 |
| 対応形式 | VST3（ARA2対応）。macOS対応時にAUを追加します。 |
| 対応DAW | 開発・動作確認の基準DAWはCakewalk Sonar（無料版）とします。REAPERを第二の検証環境とし、Studio One、Cubase等で追加検証します。 |
| 入力形式 | サンプルレート44.1〜96kHz、モノラル・ステレオ（解析はモノラル化して実施）。1クリップ最大10分を目標とします。 |
| ピッチ推定精度 | 評価用データで、RPA（正解から±50セント以内のフレームの割合）95%以上、オクターブ誤り1%未満とします（mir\_evalで測定）。 |
| ノート分割精度 | 評価用データで、ノートの開始時刻と音高が一致する割合（COnP F値、mir\_eval）80%以上を目標とします。 |
| 解析速度 | 3分の楽曲ボーカルを、CPU 8コア程度のPCで実時間の1/5以下（36秒以内）で解析します。GPUは任意とします。 |
| 再生・レンダリング | 編集中は軽量なプレビュー品質、書き出し（バウンス）時は高品質でレンダリングします。レンダリング未完了の区間は直前の結果で補い、音切れを出しません。 |
| 音質 | 半音±2の補正でアーティファクトが目立たないこと。大きな変更では、フォルマント保持を併用します。 |
| 非破壊編集 | 元音声は変更せず、編集内容のみをプロジェクトに保存します。 |
| 安定性 | 解析・推論・描画をオーディオスレッドから分離し、オーディオスレッドではメモリ確保やロックを行いません。 |
| 互換性 | 保存データにバージョン番号を持たせ、旧バージョンで編集したプロジェクトを新バージョンで開けるようにします。 |
| 操作性 | ピアノロールとの操作互換（ドラッグ移動、Ctrl+ホイールでズーム、ショートカット）を基本とし、日本語・英語UIに対応します。 |
| 費用 | 無料配布とし、ライセンス認証やオンライン通信を必須にしません。 |

## 5. アーキテクチャと技術選定

処理は「解析」「編集モデル」「レンダリング」「UI」の4層に分け、解析とレンダリングはオーディオスレッドから切り離します。

1. **解析層**: ARAから受け取った音声を非同期に解析し、F0・有声判定・ノート列・音素境界を生成します。
2. **編集モデル層**: ノートごとの編集パラメータ（ピッチ、時間、フォルマント、ゲイン）を保持し、Undo/Redoとシリアライズを担当します。
3. **レンダリング層**: 編集モデルに従い、ピッチ変更とタイムストレッチを適用した音声を生成します。ARAの再生レンダラーから要求された区間を、キャッシュから返します。
4. **UI層**: ピアノロール、波形、パラメータ操作を提供します。

| 領域 | 採用候補 | 備考 |
| --- | --- | --- |
| 言語・フレームワーク | C++20、JUCE 8 | ARAの統合機能とVST3出力を利用します。 |
| プラグイン規格 | VST3 SDK（MIT）、ARA SDK（Apache 2.0） | いずれも無料配布と両立します。 |
| ピッチ推定 | FCPE（MIT、ONNX）を主とし、RMVPE、pYINを比較対象とします。 | RMVPEは配布元によって研究用途の条件が付くため、同梱は条件確認後とします。pYINはGPU・モデル不要の代替です。 |
| ノート分割 | F0からのHMM／ルールベース、Basic Pitch（Apache 2.0）、OpenVPIのGAMEを比較します。 | 評価用データで精度を比較して決定します。 |
| 推論実行 | ONNX Runtime（CPU、任意でDirectML） | GPUが無い環境でも動作することを必須とします。 |
| ピッチ・時間加工（標準） | WORLD系ボコーダー、またはPSOLA系 | 子音保護とフォルマント保持を実装しやすい方式を採用します。 |
| ピッチ・時間加工（高品質） | PC-NSF-HiFiGAN（OpenVPI） | フォルマントを保ったままピッチを変更できます。公開重みはCC BY-NC-SA 4.0のため、本体に同梱せず任意の追加ダウンロードとします（F-17）。 |
| タイミング整列 | DTW（MFCC・onset特徴量） | ガイドと対象の音声を整列します。 |
| MIDI入出力 | JUCEのMIDIファイル機能 | SMFの書き出し・読み込みを行います。 |
| ビルド・CI | CMake、GitHub Actions | Windows版を自動ビルドします。 |
| 検証 | pluginval、mir\_eval | プラグインの規格適合とピッチ・ノート精度を自動で検査します（11章）。 |

ライブラリとモデルのライセンス（GPL系ライブラリ、非商用条件付きの学習済み重み）が配布条件と衝突しないかを、採用前に確認します。

## 6. DAW連携方式

「ボーカルに挟んで調整し、そのままDAWに反映する」操作は、ARA2対応DAWではクリップにプラグインを割り当てる形で実現します。非対応DAWでは機能を制限したキャプチャモードで動作します。

| 項目 | ARA2モード（主） | キャプチャモード（補助） |
| --- | --- | --- |
| 音声の取得 | クリップ全体をホストから直接取得します。 | 再生中にインサートで受け取った音声を記録します。 |
| 解析のタイミング | クリップ読み込み時に自動で解析します。 | 録音（キャプチャ）後に解析します。 |
| 編集内容の反映 | 再生・ミックスダウンにそのまま反映されます。 | 次回以降の再生に反映します（遅延補償の範囲）。 |
| タイミング編集 | 自由に前後へ移動・伸縮できます。 | 補償遅延の範囲内に制限します。 |
| 対応DAW | ARA2対応DAW（Cakewalk Sonar、REAPER、Studio One、Cubase等）。各DAWの動作は実機で確認します。 | VST3対応DAW全般 |

- **編集内容の保存**: ARAの状態保存機能を使い、プロジェクトに編集内容を保持します。
- **テンポ・拍子の同期**: ホストのテンポマップ・拍子情報をARA経由で取得し、グリッド表示に使います。
- **MIDIの受け渡し**: SMFのファイル出力・読み込みを基本とします。
- **対応外のDAW**: ARA2に対応しないDAWでは、タイミング編集の自由度が下がることを仕様として明示します。
- **ホストとの選択範囲連動**: DAW上で選択したクリップ・範囲を、プラグインの表示範囲に反映します（ARA2の選択範囲連携）。

## 7. 開発フェーズ

各フェーズの完了条件を満たしてから次へ進みます。期間は個人開発・週10〜15時間程度の想定です。

| フェーズ | 期間の目安 | 内容 | 完了条件 |
| --- | --- | --- | --- |
| 0. 調査・試作 | 2か月 | JUCE+ARA2のサンプル動作確認、ピッチ推定モデルの比較、評価用データの作成 | Cakewalk Sonar上で音声取得と再生差し替えができる |
| 1. MVP | 4〜6か月 | F-01〜F-08：解析、ピアノロール、ピッチ・タイミング編集、ノート分割・結合、状態保存 | 1曲のボーカルを補正し、ミックスダウンに反映できる |
| 2. v1.0 | 5〜8か月 | F-09〜F-18：フォルマント、ゲイン、MIDI抽出・適用、タイミング整列、キー検出、一括補正、ニューラル加工、A/B比較 | 非機能要件の精度・速度目標を満たす |
| 3. v1.x | 継続 | F-19〜F-21、macOS対応、他DAWの検証 | ユーザーからの不具合報告に対応できる体制がある |

公開は、フェーズ1完了時点で限定ベータ、フェーズ2完了時点で正式版（v1.0）とします。

## 8. リスクと対策

| リスク | 影響 | 対策 |
| --- | --- | --- |
| ARA2の実装難度・ホストごとの挙動差 | 開発遅延、DAWごとの不具合 | フェーズ0でJUCEのARAサンプルを動かし、Cakewalk Sonarを基準にして順次対応DAWを増やします。 |
| 基準DAWの提供形態の変更 | 検証環境の喪失 | Cakewalkは過去に無料版の終了を経ているため、REAPERを第二の検証環境として並行して維持します。 |
| 加工音質がMelodyneに及ばない | 利用者の満足度低下 | 標準方式で実用品質を確保し、ニューラル加工は選択式の拡張とします。評価用の歌声データで継続的に聴感確認します。 |
| ノート分割の誤り（ビブラート、しゃくり、ブレス） | 手動修正の増加 | F-07（分割・結合・境界編集）をMVPに含め、手動修正を短時間で行えるようにします。 |
| ニューラル推論の負荷 | 再生中の音切れ | 推論は非同期で行い、再生にはレンダリング済みの結果を使います。書き出し時のみ高品質で処理します。 |
| 評価データの偏り | 他の声質で精度が下がる | 本人の歌声に加え、公開データセットと、ボカロ系の書き出し音声で評価します。 |
| 採用ライブラリのライセンス衝突 | 配布不可 | 採用前にライセンスを確認し、GPL系はAGPL配布と整合する場合のみ使用します。 |
| 学習済みモデルの権利 | 配布不可、利用者の商用利用の制限 | MITなど制限の少ないモデルを本体に同梱します。非商用条件付きの重みは同梱せず、利用者が条件を確認して追加する形にします。 |
| 個人開発の工数不足 | 計画の遅延 | 優先度M/Sに絞り、v1.0までは機能追加をしません。 |

## 9. ライセンス・配布方針

- ソースコードはGitHubで公開し、ライセンスはAGPLv3とします。JUCE 8はAGPLv3と無料のStarterライセンスを選べますが、OSSとして公開するためAGPLv3を選びます。
- 配布物は無料のインストーラ（Windows）とし、アカウント登録・ライセンス認証・テレメトリを設けません。
- VST3 SDKは3.8以降MITライセンスのため、Steinbergとの契約は不要です。著作権表示とライセンス文を同梱します。
- 本体に同梱するモデルは、MITなど再配布と商用利用に制限の少ないものに限ります。
- PC-NSF-HiFiGANの公開重みはCC BY-NC-SA 4.0（非商用・継承）のため、本体には含めず、利用者が任意で追加する方式とします。この場合の利用条件をUIと説明書に明記します。
- 学習データや第三者の音源は同梱しません。

## 11. 検証方針

各フェーズの完了条件は、次の検証で判定します。

| 検証 | 方法 | 実施時期 |
| --- | --- | --- |
| 精度評価 | 評価用データの正解ピッチ・ノートと比較し、mir\_evalでRPA・COnP F値を算出します。 | 解析処理の変更ごと（CIで自動実行） |
| 規格適合 | pluginvalでVST3としての動作（読み込み、パラメータ、状態保存）を検査します。 | ビルドごと（CIで自動実行） |
| DSP単体テスト | ピッチ変更・タイムストレッチの出力を、基準音声との差分で検査します。 | ビルドごと |
| DAW実機確認 | Cakewalk Sonarで、読み込み・編集・保存・再読み込み・書き出しの一連を確認します。REAPERでも同じ手順を実施します。 | 各フェーズ完了時 |
| 聴感評価 | 本人の歌声とボカロ系の音声で、補正前後を聴き比べてアーティファクトを確認します。 | 各フェーズ完了時 |

評価用データの正解は、本人の歌声の録音時に作成したMIDI（歌った旋律）を使います。公開データセットは、ライセンスを確認したうえで評価のみに使用し、配布物には含めません。
